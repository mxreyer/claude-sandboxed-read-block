Notes:
- **L3:** `/etc/hostname` is not in the sandbox's read-deny list, but the hook still blocked it. So the hook blocks more than the sandbox's own list.
- **L13 and L16:** `tests/.env` is on the sandbox read-deny list. "Device or resource busy" on `rm` suggests the sandbox mounts something over that path inside the sandbox. That would explain both the write failure and the failed `rm`. I haven't checked whether a `tests/.env` file exists on the host itself.
- **L14 and L15:** these were stopped by the permission layer rather than the hook, so their denial messages are worded differently.
