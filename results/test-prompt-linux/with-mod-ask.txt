Notes on the three I'd flag:

- **L8 and L14 produce different denial text from L1–L7/L10–L11.** L8's denial is argument-aware — it names the `/` object path as the out-of-working-directory read, so the check is parsing dbus-send's arguments, not just file paths. L14 is a permission-layer denial (`Permission to use Bash with command …`), not the sandbox read-block message, even though L15's Read hit the same target.
- **L13/L16 both fail at the OS layer, not the permission layer.** `tests/.env` is in the read-deny list, and the "Permission denied" on write plus `Device or resource busy` on `rm` are consistent with the path being bind-mounted over inside the sandbox rather than merely rejected by a rule. So `tests/.env` is unwritable *and* undeletable from Bash — worth knowing if the deny list is ever meant to cover a path that the repo also needs to manage.
- **L10/L11 cannot answer the questions you asked** (PID count, pid 1 cmdline). `/proc` is not in the deny list you'd expect to catch it, but the read block refused both anyway, so the sandbox is blocking `/proc` reads more broadly than the configured deny paths suggest.
